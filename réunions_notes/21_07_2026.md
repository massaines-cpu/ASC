# 1. Retour sur le ParticipantDataset

Nous avons revu la logique permettant de transformer un indice global (`idx`) en :

- un indice de fichier (`file_index`)
- un indice de participant (`participant_index`)

Code concerné :

```python
file_index = idx // 2
participant_index = idx % 2
```

## À retenir

Chaque fichier `.npy` contient une dyade, donc **deux participants**.

L'objectif est de transformer un indice unique fourni par PyTorch en :

- quel fichier charger ;
- quel participant extraire dans ce fichier.

Amel insiste sur le fait que je dois comprendre cette logique et ne pas simplement utiliser la formule.

La première boucle d'entraînement fonctionne :

# 3. Ajouter une boucle sur les époques

La prochaine étape consiste à placer toute la boucle d'entraînement dans une boucle :

```python
for epoch in range(number_of_epochs):
```

Une époque correspond à un passage complet sur tous les batches du jeu d'entraînement.

---

# 4. Sauvegarder l'historique d'apprentissage

Aujourd'hui, la variable :

```python
average_loss
```

est écrasée à chaque époque.

Il faut créer un tableau permettant de conserver l'historique :

```python
train_losses = []
```

Puis à la fin de chaque époque :

```python
train_losses.append(average_loss)
```

L'objectif est de pouvoir tracer ensuite la courbe d'apprentissage.

---

# 5. Ajouter la validation

Après chaque époque, il faut lancer une phase de validation.

Principe :

- utiliser le `validation_loader` 
- effectuer uniquement le **forward** 
- calculer la loss de validation 
- ne pas faire de `backward()` 
- ne pas faire de `optimizer.step()`

Cette étape permet d'évaluer le modèle sur des données qu'il n'a jamais vues.

---

# 6. Sauvegarder également la validation

Créer un second historique :

```python
validation_losses = []
```

À chaque époque :

```python
validation_losses.append(validation_loss)
```

À la fin de l'entraînement, on disposera donc de deux courbes :

- train loss ;
- validation loss.

---

# 7. Observer le comportement du modèle

L'objectif est de tracer les deux courbes afin de suivre l'évolution du réseau.

Cas attendu :

- la train loss diminue ;
- la validation loss diminue également.

Lorsque la validation commence à stagner, il est généralement temps d'arrêter l'entraînement.

Si la train loss continue de diminuer mais que la validation augmente, cela indique un **surapprentissage (overfitting)**.

---

# 8. Cross-validation (à faire plus tard)

Cette étape ne doit être réalisée qu'une fois la boucle d'entraînement + validation entièrement maîtrisée.

Méthode retenue :

**Leave-One-Subject-Out (LOSO)**

Principe :

- laisser un sujet de côté pour la validation ;
- entraîner sur tous les autres sujets ;
- recommencer pour chaque sujet.

Cela revient à entraîner plusieurs modèles.

L'objectif est ensuite de rapporter :

- la moyenne des performances ;
- leur variabilité.

Cette étape permet de vérifier que les performances ne dépendent pas d'un découpage particulier des données.
